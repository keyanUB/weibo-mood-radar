# Weibo Mood Radar · 微博热点情绪周刊

基于每天热门 30 条微博及每条前 100 条高赞评论，汇总**每周热点事件、事件评论情绪与月度趋势**。只提供周报和月报；每天是数据采样频率。

[周报/月报归档](reports/README.md) · [数据接口](docs/DATA_SOURCE.md) · [统计方法](docs/PRODUCT_SPEC.md) · [部署到 GitHub](docs/GITHUB_SETUP.md) · [贡献指南](CONTRIBUTING.md) · [MIT License](LICENSE)

> 当前版本提供可运行的分析、报告与 GitHub Actions 工作流。真实数据接口尚未配置，下方演示报告来自虚构样本，不是当前微博舆情。情绪得分为未校准词典基线，不是民众人数占比。

## 最新周报与月报

每周一更新上一个已结束的自然周。README 展示北京时间起止日期、数据覆盖、热点事件、评论样本量和情绪得分。当月报告随周报累计更新，每月 1 日归档上月报告。

## 本地运行

Python 3.11 或更新版本。分析流程不依赖第三方 Python 库。

在仓库根目录安装并运行：

```console
python -m pip install -e .
weibo-mood-radar report --input examples/snapshots.json --period week --anchor 2026-06-04 --as-of 2026-06-08 --output reports/demo/weekly/2026-W23.json
weibo-mood-radar publish --input examples/snapshots.json --demo --as-of 2026-06-08
```

生成月报：

```console
weibo-mood-radar report --input examples/snapshots.json --period month --anchor 2026-06-01 --as-of 2026-06-08 --output reports/demo/monthly/2026-06.json
```

测试（无需安装依赖，PowerShell）：

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -v
```

导入真实数据：输入文件或目录内的 JSON 须符合[快照格式](docs/DATA_SOURCE.md)，并包含该统计窗口的全部日快照。

```console
weibo-mood-radar publish --input data/snapshots
```

不指定 `--as-of` 时，按当前北京时间生成最新已结束周、当月累计及上月报告。`--as-of` 是不包含当天的截止日期，可用于历史重算。

## GitHub 自动更新

`.github/workflows/reports.yml` 已配置以下任务：

| 任务 | 北京时间 | 结果 |
| --- | --- | --- |
| 每周更新 | 周一 09:17 | 归档上周事件和情绪，更新 README 与当月累计 |
| 月末归档 | 每月 1 日 09:37 | 生成上月聚合报告，更新 README |
| 手动更新 | Actions → Run workflow | 重跑并补齐返回数据中的历史周/月 |

在仓库 Secrets 中配置 `DATA_SOURCE_URL`，需要鉴权时再配置 `DATA_SOURCE_TOKEN`。接口应提供上月 1 日至本次运行前一天的**每日历史采样快照**；周一查询一次当前热门榜无法还原过去一周的样本。

工作流只提交 README 和聚合报告，原始评论保留在临时工作目录。未配置接口时，每周仍更新日期和“暂无数据”状态；已配置接口但响应失败时任务会失败并保留已有报告。不会用演示数据顶替真实结果。实际启用步骤见[部署说明](docs/GITHUB_SETUP.md)。

GitHub 的定时任务按 UTC 调度，可能延迟，且只在默认分支运行；公开仓库长期无活动时可能暂停定时任务。参见 [GitHub 官方调度说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。

## 分析口径

- 每天按排名选取 30 条唯一微博，每条按点赞数选前 100 条唯一非空评论；不足时保留实收数并展示缺口。
- 周期按采样时间归属，统一北京时间。周一至周日为一周，自然月为一月。
- 同一周期内按“微博 ID + 评论 ID”去重，重复评论使用最近一次采样的文本和点赞数。月报从评论重新汇总，不平均周报分数。
- 微博正文用于事件摘要，评论用于情绪评分。相同 `event_id` 的微博合并为一个事件；未提供时逐微博展示，不把宽泛话题标签当成同一事件。
- 喜悦、愤怒、悲伤、焦虑、厌恶、惊讶、中性/未识别共 7 项，各项 0–100，总和约 100（有四舍五入误差）。
- 每条评论权重为 `1 + ln(1 + 点赞数)`。热点按去重评论数排序，评论数相同时参考榜单排名。
- 高赞评论和热门榜存在选择偏差。指标描述本项目样本，不能推断全体网民；当前模型也尚不能可靠处理反话、讽刺和复杂语境。

代码采用 MIT 许可。该许可不授予第三方微博内容的再分发权；仓库自带的演示数据为虚构文本。
